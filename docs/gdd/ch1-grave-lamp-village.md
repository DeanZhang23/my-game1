## 1. 本文是什么 / 不是什么

**是：** 玩家进入墓灯村之后怎么走完「选人 → 出村 → 打第一场 → 回村休整」的可玩开场。只保留开场真正需要的地点和 NPC，并写清如何接到已锁定的放置自动战。

## 2. 一句话与开场循环

玩家在墓灯村编一支最多 5 人的队伍，从村门出征，进入一场固定的开场裂隙遭遇（沿用已有 TestArena 战场与敌人预设）；打完无论胜负都回到墓灯村，自动休整后可再次出征。

**开场循环（已锁定）：**

1. 玩家身处墓灯村（枢纽），不是 TestArena。
2. 可查看少数关键地点，只与必要 NPC 交谈。
3. 在编队板从正式 8 人中选出最多 5 人（开场 8 人全部可选，见 §7）。
4. 经村门出征，进入**第一章开场第一场战斗**。
5. 该战使用已锁定流程：Setup（把已选单位放到我方 3×3）→ Countdown → AutoCombat → Resolve。
6. 结算后回到墓灯村（胜利或失败皆回）。回村时执行 §8 的休整。失败不是 Demo 卡死，可再次出征。

村内「选谁出征」和战场「3×3 摆位」是两步，不要把村庄做成 TestArena，也不要把摆位缩进村里。

## 4. 玩家进村后能做什么

进入第一章 Demo 后，玩家直接在墓灯村，没有登录墙，也没有把测试场当开场。灰盒用键盘 + 鼠标即可，不规定正式大界面。

开场在村里可以：

| 可做 | 说明 |
|---|---|
| 查看枢纽与金币 | 始终可见档案金币（复用 `ui.gold`）。开场为 0。 |
| 与见证者交谈 | 唯一必要 NPC：说明此地、指向编队板和村门；队伍合法时也可发起出征确认。 |
| 在编队板选人 | 从正式 8 人中勾选最多 5 人；不足 1 人不能出征。 |
| 走向村门出征 | 唯一战斗出口，目的地固定，见 §7。 |
| 查看未开张摊位 | 只能得到「尚未开张」的提示，不进入商店。 |

开场在村里不能：买东西、花钱、打开路线地图、改战斗规则、指定骰子目标、把单位直接摆进 3×3（摆位只在出征后的 Setup）。

回村后可改编队并再次出征。休整在回村时自动完成，不必再点「休息」建筑。

## 7. 编队与出征：如何接上已锁定的放置自动战

本节只写衔接。战斗规则、公式、骰子、寻敌与黄金文件一律以 `docs/gdd/m0-test-arena-placement.md` 为准，本文不重述、不改写。

### 7.1 正式 8 人（全部可进入开场编队）

仓库没有「某人开场未解锁」的规则。风格指南与正式名单把以下 8 人定为可玩盟友；TestArena 中默认两人在场、其余六人在待命，但 8 人都可以摆上 3×3。开场编队同样 **8 人全部可选**，上限 5 人出征。

战斗与编队必须使用下面的**仿真单位 ID**，不要自造 `unit_ashguard` / `unit_riftmage`。灰烬卫士与裂隙术士的美术 ID 是 `ashguard` / `riftmage`，当前绑定在两个占位单位 ID 上，显示名走已有 `unit.placeholder_*.name`。

| 单位 ID | 显示名（已有 key） | 美术 ID | 职责 `role` | 开场默认是否入队 |
|---|---|---|---|---|
| `unit_placeholder_melee` | 灰烬卫士 / Ashguard（`unit.placeholder_melee.name`） | `ashguard` | `melee` | 是 |
| `unit_placeholder_caster` | 裂隙术士 / Riftmage（`unit.placeholder_caster.name`） | `riftmage` | `ranged` | 是 |
| `unit_oathblade` | 烬誓剑士 / Oathblade（`unit.oathblade.name`） | `oathblade` | `melee` | 否 |
| `unit_chainjudge` | 锁链判官 / Chainjudge（`unit.chainjudge.name`） | `chainjudge` | `melee` | 否 |
| `unit_lampsister` | 墓灯修女 / Lampsister（`unit.lampsister.name`） | `lampsister` | `ranged` | 否 |
| `unit_misthunter` | 雾行猎手 / Misthunter（`unit.misthunter.name`） | `misthunter` | `ranged` | 否 |
| `unit_boneapostle` | 骨匣使徒 / Boneapostle（`unit.boneapostle.name`） | `boneapostle` | `ranged` | 否 |
| `unit_bloodacolyte` | 血契侍从 / Bloodacolyte（`unit.bloodacolyte.name`） | `bloodacolyte` | `ranged` | 否 |

后六人的战斗面板与技能，按正式名单是从对应占位近战 / 远程复制而来。开场不得改这些数值，也不得按风格指南里的职能简述另做技能。

编队规则：

- 最多勾选 5 人，最少 1 人才能出征。
- 默认已勾选 `unit_placeholder_melee` 与 `unit_placeholder_caster`（与 TestArena 默认出场一致）。玩家可换成另外的正式单位，或补到 5 人。
- 未入选的单位本场不进入 Setup 待命，也不参战。
- 村内编队只决定「谁出征」，不决定格子。

### 7.2 唯一目的地：开场裂隙遭遇

不是路线地图，不是 Boss，不是两阶段，不新增战斗规则。

| 字段 | 值 |
|---|---|
| 遭遇 ID | `encounter_ch1_opening_rift`（**临时**） |
| 临时显示名 | 村外裂隙（`encounter.ch1.opening_rift.name`） |
| 战场 | 现有 `Assets/Scenes/TestArena.unity`（风格指南：Rift Battlefield，不是墓灯村） |
| 敌人 | 沿用 TestArena 预设：`unit_placeholder_enemy`（锈蚀步卒 / Rustsoldier，`unit.placeholder_enemy.name`）各 1 名，站在 `enemy_c1`、`enemy_c2` |
| 敌方数值与摆法 | 全部沿用现有定义与预设，不改、不扩正式敌人名单 |

### 7.3 出征如何接到已锁定流程

1. 玩家点村门（或见证者的出征确认）。队伍为 0 人则不可出发，提示复用或并列于 `ui.formation.illegal`（空阵不可出征）。
2. 离开村庄，进入开场裂隙遭遇的 **Setup**：已选出的 1–5 人全部出现在待命（`ui.formation.bench`），**格子上先空着**。玩家在此把他们放到我方 3×3。规则与现有 Setup 相同：上限 5、一格一人、空阵不能点出征（`ui.commit`）、Countdown 后不可再改阵。
3. 点出征后进入已锁定的 Countdown（约 3 秒）→ AutoCombat → Resolve。战前不掷骰、不锁骰、不重掷；战斗中命运能量与自动发放效果全按补丁执行；战斗不因掷骰暂停。
4. Resolve 后（胜利 / 失败 / 超时）回到墓灯村，先执行休整，再让玩家自由行动。

灰盒可保留 TestArena 的种子输入，供对照。种子 **424242**、默认两人、不改阵的黄金路径（失败 10.800 秒、金币 0）仍是仿真回归，预期如此。村庄流程不得为了这场开场去改公式、骰子或黄金文件。玩家若在村里换成其他人，或在 Setup 里改了站位，那是另一场战斗，不要求复现黄金文件。

## 8. 休整、金币、商店

### 8.1 休整（开场要做）

每次战斗结算并返回墓灯村时自动执行，不必与建筑或 NPC 互动。无永久死亡，阵亡单位回村后再次可编入。

| 项目 | 回村后的状态 |
|---|---|
| 存活单位生命 | 回满 |
| 护盾 | 全部到期清除 |
| 队伍 `fateEnergy` | 重置为 0 |
| 各单位技能能量 | 重置为 0 |
| 本场骰子周期 | 清除（下一场仍按规则最多掷 1 次） |
| 本场阵亡的我方单位 | 重新可编入、可出征，生命为满 |
| 档案金币 | **不清零**（见下） |

### 8.2 金币（可获得、可显示，开场无消耗）

沿用已锁定规则：币面在确认后计入本场胜利金币；只有胜利才把该金币加入档案；失败或超时为 0。公式与面值不改。

开场 Demo 档案有一笔累计金币，初始为 0。胜利则把本场 `battle_end` 的金币加上去；回村或再出征不清零。本开场只要求同一 Demo 档案 / 同一次游玩过程内累计并显示（复用 `ui.gold`）。跨进程存档留给日后，不在本文展开。开场没有任何金币消耗口。

### 8.3 商店购买（砍掉）

村里可以有一个未开张摊位（`loc_ch1_closed_stall`）。交互只提示尚未开张。不做商店界面、库存、价格、购买、店主。
