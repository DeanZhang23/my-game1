## 1. 新的核心循环

1. **Setup（战前）：** 把最多 5 个单位放到 3×3 我方格（只决定出生点）。 **战前不掷骰、不加骰子加成、不能锁骰、不能重掷。**
2. 点 **出征** → `Countdown`（仍约 3 秒）。
3. **AutoCombat：** 双方自动寻敌、移动、进入射程后自动攻击。战斗中 **不因战术窗口停手**，也不再出现 `TacticalWindow`。掷骰期间战斗同样继续。
4. 战斗过程中积攒 **骰子能量**。能量 ≥ 50 时玩家可掷一次 3 枚骰，然后确认（或 6 秒 / 战斗结束自动确认）；效果在确认时按 §5.3 **自动** 落到对应单位上，玩家不用指定目标。
5. **Resolve：** 一方全灭，或 150 秒超时（失败）。币面金币仍仅胜利发放。

## 2. 寻敌、移动、攻击

**双方都会动。** 寻敌已锁定，不再修改。

### 2.1 选目标（已锁定）

每个单位始终最多锁定 1 个敌方存活目标。排序：

1. 距离自己更近（仿真平面直线距离）的优先；
2. 距离相同，则当前生命更低的优先；
3. 仍相同，则稳定 ID（槽位 ID）字典序更小的优先。

每 **0.25 秒** 用同一规则重选一次（目标死亡时立即重选）。全程确定性，不另引随机。

### 2.2 移动

- 3×3 格子只决定 **出生点**（见 §3）。进入 AutoCombat 后，单位在 TestArena 的 2D 平面上连续移动，不再吸附格子。仍是纯 2D 等距，禁止 3D 寻路或 3D 碰撞管线。
- 未进入攻击射程时：每帧直线走向 **当前目标此刻的位置**，速度为该单位的 `moveSpeed`。
- 不得走出场地边界（夹紧在 TestArena 矩形内）。
- M0 **不做** 障碍寻路、阻挡、分离力。允许单位重叠，以保证黄金种子确定性。

### 2.3 接触与攻击

- 与当前目标距离 `<= attackRange` 即进入射程：停止移动，按原攻速公式出普攻；能量满且在射程内则放技能。伤害公式仍用主文档 §8，一律不变。
- 目标走出射程、死亡或被换目标后：若新目标不在射程内，恢复移动。

### 2.4 占位单位新增字段

原生命 / 攻击 / 法强 / 护甲 / 魔抗 / 暴击 / 攻击间隔 / 单位技能能量 **全部不动**。只加移动、射程，以及给骰子用的职责标签：

| ID | role | moveSpeed | attackRange |
|---|---|---|---|
| `unit_placeholder_melee` | `melee`（近战） | 3.0 单位/秒 | 0.9 |
| `unit_placeholder_caster` | `ranged`（远程） | 2.5 单位/秒 | 3.5 |
| `unit_placeholder_enemy`（近战） | `melee` | 3.0 单位/秒 | 0.9 |

职责写在单位定义（ScriptableObject）上，不由站位推断。M0 不扩展正式名册。

**场地尺度（M0 默认）：** 相邻格子中心距 1.5；我方前排中心到敌方前排中心 4.0。近战开局不在射程内，需走上约 1 秒。

## 3. 3×3 格子

**格子只作战前放置，只决定出生点。** 骰子效果不再按前 / 中 / 后排发放。

- Setup 规则与主文档 §6 相同（上限 5、一格一人、空阵不能出征、Countdown 后不可再改阵）。
- 开战后 3×3 不再约束站位，也不再根据所在格子把骰子打到前排或后排。
- 出征时仍可记录格子快照（便于日后用），但 **M0 的骰子结算不读这份快照**。

## 4. 骰子能量（最小可测方案）

新增本场资源 `fateEnergy`（骰子能量）。与单位技能能量分离：技能能量仍按单位各自的「能量 / 秒」和技能消耗 100 运转；骰子能量是 **我方队伍共享的一条池**。

### 4.1 怎么攒

开战时为 0，上限 **100**，溢出丢弃。只在 AutoCombat 期间增长。只统计 **我方** 造成的事件（敌方不积攒、M0 敌方不掷骰）。

| 来源 | 规则 | ID |
|---|---|---|
| 造成伤害（扣血） | 我方把伤害打到敌方护盾或生命时，按实际扣减量累计；每满 10 点得 1 点骰子能量，余数保留到下次 | `fate_from_damage` |
| 击杀 | 我方击杀 1 名敌人：+15 | `fate_from_kill` |
| 现有技能能量体系 | 我方单位获得技能能量时，每获得 5 点技能能量，队伍 +1 点骰子能量（余数按单位分别保留） | `fate_from_skill_energy` |
| 释放技能 | 我方单位成功释放 1 次技能：+8 | `fate_from_skill_cast` |

例子（供单测）：造成 16 点伤害 → 池 +1，余 6；再造成 16 → 池 +2，余 2。近战「能量 / 秒 = 8」则每秒 +1 骰子能量并余 3。击杀 +15 与伤害分开加，不互相折算。

### 4.2 阈值与操作花费

M0 **每场只有 1 轮** 骰子周期：能量够了掷 **一次** 3 枚，然后确认。没有重掷。

| 操作 | 花费 | 条件 |
|---|---|---|
| 掷骰 `dice_roll` | **50** | AutoCombat 中、本场尚未掷过、当前能量 ≥ 50 |
| 确认 `dice_commit` | 0 | 已掷未确认 |

**没有重掷操作，也不花费能量重掷。** 能量不足时掷骰按钮不可用，战斗继续。点掷骰时立刻扣 50，不能透支。

### 4.3 谁来操作

只有 **玩家**。M0 敌人不掷骰、不抢能量。灰盒用按钮：掷骰 / 确认。黄金种子测试用脚本在指定逻辑时刻调用同一 API（见 §6）。玩家 **不能** 也 **不必** 把效果拖给某个单位。

### 4.4 会不会暂停自动战斗（已确认：不暂停）

掷骰、等待确认期间，双方单位继续寻敌、移动、攻击，骰子能量继续积攒（但本场已掷过就不能再掷第二次）。

- 掷出后玩家有 **6 秒** 可提前确认。
- 超时未确认：自动确认（`dice_commit`，原因 `timeout`）。
- 若战斗在确认前结束：进入 Resolve 前自动确认，让已掷出的面（例如币）仍能结算。
- 若整场从未达到 50 或玩家从未掷骰：本场无骰子加成，合法结束。

## 5. 战斗中的骰子规则（无锁骰、无重掷）

### 5.1 删除的内容

- 删除 **锁骰**。
- 删除 **重掷**（不要花能量全重掷，也不要「先重掷再叠加裂纹」的流程）。
- 删除战前掷骰、战前结算、出征时的骰子加成。
- 删除「把骰子效果拖到单位上」的操作与 UI。
- 删除 `TacticalWindow`。状态机：`Setup` → `Countdown` → `AutoCombat` → `Resolve`。AutoCombat 不暂停。同调 **只保留数值 ×1.80**，不再解锁战术窗口，也不另做自动专属战术。

### 5.2 一轮怎么走

1. 能量 ≥ 50，玩家点掷骰：扣 50，立刻掷出 3 枚（六面等权，随机仍走本场种子）。
2. 玩家确认，或 6 秒超时 / 战斗结束自动确认。
3. 确认时按这 3 面结算双生 / 同调，并按 §5.3 **自动** 把效果落到对象上，写 `dice_commit` 与 `combo_resolved`（日志列出每个效果的实际作用单位 ID）。本场结束，不能再掷。

万能符印、组合判定仍用主文档 §4.4（自动指定到最高档组合）。没有锁骰、没有重掷、没有玩家选目标。

### 5.3 效果作用对象（Dean 锁定）

确认时系统按骰面（或连携定义）自动选择作用对象，**不要玩家拖、点、指定格子**。通用规则：

| 作用类型 | 规则 | 数据字段示例 |
|---|---|---|
| 近战 | 对所有我方存活、`role = melee` 的单位生效 | `target_all_melee` |
| 远程 | 对所有我方存活、`role = ranged` 的单位生效 | `target_all_ranged` |
| 全队 / 战场 | 对所有我方存活单位，或对整场结算（如金币） | `target_all_allies` / `target_battle` |
| 指定英雄 | 只对数据里写明的那一个单位 ID 生效；场上没有该单位则该效果落空（仍记日志） | `target_hero` + `heroId` |
| 两英雄连携 | 只对数据里写明的那两个单位 ID 生效；缺任何一人则该连携落空 | `target_hero_link` + 两个 ID |

只作用于 **我方**。敌方即使也是近战 / 远程，也不吃我方骰子。阵亡单位不吃新的单位效果。场上没有符合类型的单位（例如掷出剑但没有存活近战）时，该面的单位效果落空，组合仍然按骰面结算。

**M0 六面怎么套这条规则（数值不变，只改对象）：**

| 面 | 作用类型 | 确认时 |
|---|---|---|
| 剑 / 锋刃 | 近战 | 全部我方近战：攻击 +12%（可被双生 / 同调放大），并立即获得锐意层数。不再按前排，也不再给远程加攻击。 |
| 盾 / 壁垒 | 近战 | 全部我方近战：护甲 +8，并立即获得 15% 最大生命护盾（从此时起算 8 秒）。不再按前排。 |
| 星 / 秘仪 | 远程 | 全部我方远程：**立即** +20 技能能量；之后技能伤害 +10%。不再按后排。 |
| 羽 / 疾行 | 全队 | 全队攻速 +15%；每个我方单位当前技能冷却 −1 秒（最低 0），若首个技能尚未释放则其首个技能冷却仍按主文档 −1 秒。 |
| 币 / 贪欲 | 战场 | 本场胜利金币 +6（确认在失败结算前完成才算数；自动确认发生在 Resolve 之前）。 |
| 颅 / 献祭 | 全队 | 全队立即损失 5% 当前生命（至少留 1 点）；获得本场临时万能符印，参与当次组合判定。 |

指定英雄、两英雄连携是通用规则，留给后续写了正式名册或连携骰面之后使用。 **M0 这六面都不指定英雄、也没有两人连携，不要为此提前做正式名册或拖拽 UI。**

### 5.4 裂纹与腐蚀（M0 暂不启用）

主文档里的裂纹（`status_crack`）与腐蚀（`mod_corrosion`）原先只靠「额外重掷」叠层。本补丁删除重掷后，M0 **没有** 获得裂纹的途径。

**M0 不启用裂纹和腐蚀**：不积层、不乘 1.15、不做替代获取手段，也不另发明大机制。规则与数值保留在主文档中，留给后续切片（若当时有非重掷的来源再启用）。

## 6. 黄金种子 424242 与公式：必须改 / 尽量不动

现有测试：`GoldenSeedTests.cs` 种子 **424242**，脚本是战前「锁第 0 枚 → 重掷 1 次 → 出征 → RunToEnd(Skip)」。锁骰、重掷与战前掷骰均已作废，脚本必须整段改写。

### 必须改

- 去掉锁骰、重掷、战前掷骰、`TacticalDecision` / `tactical_window_*`，以及裂纹 / 腐蚀的 M0 触发。
- 骰子单位效果改为按 `role` / 指定 ID 自动生效，不再按前中后排快照。
- 黄金脚本改为：出征（无骰）→ 进入 AutoCombat → 按确定性规则在能量首次达到 50 时掷骰一次 → 确认（或依赖 6 秒超时）→ 跑到结束。建议黄金文件改名为 `m0-midcombat-dice.txt`，或覆盖旧文件并在 PR 说明脚本已替换。
- 种子值可继续用 **424242** 作为本场随机种子，但骰子现在开战后才掷且不再重掷，**旧的骰面序列不必保持**。
- 占位单位增加 `role`、`moveSpeed`、`attackRange`；日志增加 `fate_energy`、`dice_roll`、`dice_commit`（含实际作用单位）、以及 `unit_target` / `unit_engage`。不要有 `dice_reroll`、`dice_lock`、`tactical_window_*`。不要逐帧记位移。

### 尽量不动

- **§8 全部公式与 `FormulaTests` 不动。**
- 骰面数值、双生 / 同调系数、献祭留 1 点、币面只在胜利发金币，均不动。
- 占位单位除 `role` / 移动 / 射程外的战斗面板不动。
- 3×3 放置与出生点规则不动（只是骰子不再读前中后排）。

可另加几条不依赖整场回放的单测：造成 16+16 伤害的能量余数、能量 49 不能掷、50 能掷并扣到 0、确认不扣费、无重掷入口、剑只加在近战不加在远程、星只加在远程、场上无近战时剑效果落空、未暂停时掷骰前后单位仍在移动。
