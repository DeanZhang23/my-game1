## 1. 新的核心循环

1. **Setup（战前）：** 把最多 5 个单位放到 3×3 我方格；掷 3 枚命运骰，可锁骰、重掷、叠裂纹、结算双生 / 同调。骰子 **只在开战前** 使用。
2. 点 **出征** → 按最终骰面一次性加上本场加成（见 §4）→ `Countdown`。
3. **AutoCombat：** 双方单位自动寻敌、自动移动、进入射程后自动攻击。战斗中 **不再出现战术窗口，也不再停下来等玩家操作**。
4. **Resolve：** 一方全灭，或 150 秒超时（失败）。币面金币仍仅胜利发放。

## 2. 寻敌、移动、攻击

**双方都会动。** 我方与敌方用同一套规则。

### 2.1 选目标（M0 默认，见文末问题）

每个单位始终最多锁定 1 个敌方存活目标。排序：

1. 距离自己更近（仿真平面直线距离）的优先；
2. 距离相同，则当前生命更低的优先；
3. 仍相同，则稳定 ID（槽位 ID）字典序更小的优先。

每 **0.25 秒** 用同一规则重选一次（目标死亡时立即重选）。全程确定性，不另引随机。

### 2.2 移动

- 3×3 格子只决定 **出生点**（见 §3）。进入 AutoCombat 后，单位在 TestArena 的 2D 平面上连续移动，不再吸附格子。仍是纯 2D 等距表现，禁止 3D 寻路或 3D 碰撞管线。
- 未进入攻击射程时：每帧直线走向 **当前目标此刻的位置**，速度为该单位的 `moveSpeed`。
- 不得走出场地边界（夹紧在 TestArena 矩形内）。
- M0 **不做** 障碍寻路、阻挡、分离力。允许单位重叠，以保证黄金种子确定性。

### 2.3 接触与攻击

- **接触 / 进入射程：** 与当前目标的距离 `<= attackRange`。
- 进入射程后 **停止移动**，按原攻速公式出普攻，能量满且在射程内则放技能。伤害公式仍用主文档 §8，一律不变。
- 目标走出射程、死亡或被换目标后：若新目标不在射程内，恢复移动。
- 没有「额外的接触伤害」或独立近战状态机；射程就是开战条件。

### 2.4 占位单位新增字段（仅补移动与射程）

原生命 / 攻击 / 法强 / 护甲 / 魔抗 / 暴击 / 攻击间隔 / 能量 **全部不动**。只加：

| ID | moveSpeed | attackRange |
|---|---|---|
| `unit_placeholder_melee` | 3.0 单位/秒 | 0.9 |
| `unit_placeholder_caster` | 2.5 单位/秒 | 3.5 |
| `unit_placeholder_enemy`（近战） | 3.0 单位/秒 | 0.9 |

**场地尺度（M0 默认，便于测）：** 相邻格子中心距 1.5；我方前排中心到敌方前排中心 4.0。近战开局不在射程内，需要走约 1 秒再开打；后排法师通常稍后即可开火。

## 3. 3×3 格子与前 / 中 / 后排

**最小改动方案：格子只作战前放置；位置加成在出征时快照，之后整场保留。**

- Setup 阶段：规则与主文档 §6 相同（上限 5、一格一人、空阵不能出征、Countdown 后不可再改阵）。
- 出征瞬间：按 **当时所在格子** 判定前排 `*_c*`、中排 `*_b*`、后排 `*_a*`，结算剑（前排锐意）、盾（前排护盾）、星（后排初始能量）。中排仍只吃全队效果。
- 开战后单位离开格子 **不重新判定** 前中后排，也不取消已加上的锐意 / 护盾 / 能量。这样不用做「移动中的区域判定」，也保留放置的意义。
- 开战后 3×3 不再约束站位，不限制谁可以走向谁。

## 4. 删除战术窗口；骰子只在开战前生效

### 4.1 状态机（替换主文档 §5）

`Setup` → `Countdown` → `AutoCombat` → `Resolve`

- **删除 / 停用** `TacticalWindow`。Simulation 在 AutoCombat 期间不暂停、不接受确认或跳过。
- 主文档 §5.4 的「8 秒打开窗口」整段作废。事件日志不再产生 `tactical_window_*`。
- 同调（3 同面）**只保留数值 ×1.80**，不再解锁战术窗口，M0 也不另做「自动释放的专属战术」（避免扩 scope）。双生规则不变。

### 4.2 骰子何时生效

- 掷骰、锁骰、重掷、裂纹，全部只在 Setup、点出征之前。战斗中 **禁止再掷、再锁、再重掷**。
- 点出征（`dice_commit`）时一次性结算：组合、全队 / 位置加成、献祭扣血与万能符印、裂纹满 3 层则挂上本场腐蚀。
- 这些效果作为本场持续修正存在（护盾仍按 §8.4 在进入 AutoCombat 时挂上并 8 秒后消失；锐意仍按命中消耗）。不是每回合刷新，也不是战斗中再掷出的新结果。

## 5. 黄金种子 424242 与公式：必须改 / 尽量不动

现有测试：`tests/Echoes.Simulation.Tests/GoldenSeedTests.cs` 使用种子 **424242**，脚本为锁第 0 枚骰 → 重掷 1 次 → 出征 → `RunToEnd`（目前还传入 `TacticalDecision.Skip`）。黄金文件：`tests/Echoes.Simulation.Tests/golden/m0-lock0-reroll.txt`。

### 必须改

- 状态机与 API：去掉战术窗口参数和 `tactical_window_*` 事件。
- **整场战斗** 的黄金文件必须重录（`UPDATE_GOLDEN`）。单位会移动，交战时刻、伤害时间戳、时长，甚至击杀顺序都可能变，旧战斗段不再有效。
- 日志可增加 `unit_target`、`unit_engage`（进入射程）。**不要**逐帧记录位移。
- 占位单位定义增加 `moveSpeed`、`attackRange`。

### 尽量不动

- 种子值仍为 **424242**；战前脚本仍为「锁第 0 枚 → 免费重掷 1 次 → 出征」。不要改掷骰随机流程。
- 建议验收时拆成两段：从开战到 `dice_commit` / `combo_resolved` 的事件前缀应与旧黄金文件一致（不一致就是骰子被改坏了）；`AutoCombat` 之后用新黄金文件。
- **§8 全部公式与 `FormulaTests` 不动**（普攻 / 法术、暴击、攻速下限 0.35、护盾先于生命、献祭至少留 1 点、金币向下取整）。
- 骰面数值、双生 / 同调系数、裂纹与腐蚀、献祭与符印规则不动。
- 占位单位除移动 / 射程外的战斗面板不动。
- 布阵「哪一格算前排 / 后排」的判定不变，只是改为出征时快照。
